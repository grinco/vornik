Credential activity — who uses Vornik, how much, and how often

From memory_retrieval_audit and task_llm_usage, which record the credential directly — so these rows are real today, independent of task attribution. Credentials the system issues to itself (a fresh key per task execution, plus warm-pool keys) are folded into one row each rather than listed individually — they are the agent runtime doing someone's work, not separate users. Active days is the retention signal: a credential active on most days is a habit, one with a single busy day is a trial. Memory writes are deposits into project memory — teaching Vornik something rather than asking it, which is the stronger adoption signal. Chat activity is attributed per CHANNEL OPERATOR (telegram:42, slack:U123) and does not yet merge with the same person's API-key activity: linking channel identities to one account is designed but not wired.
